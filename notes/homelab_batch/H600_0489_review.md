## Finding
The function _ue_exec_locked does not handle the case where the file EXEC_OUT exists but is not modified within the timeout period. This can lead to a false return of None, even if the execution is still in progress.

## Evidence
- start_bridge.py:168 - if os.path.exists(EXEC_OUT) and os.path.getmtime(EXEC_OUT) > t0:

## Suggested fix
Modify the condition to check for the existence of the file and the modification time, and also add a check for the file size to ensure that the file is not empty and has been written to.

## Validation needed
The developer should run the function with a known execution that takes longer than the timeout period and verify that it does not return None prematurely.
