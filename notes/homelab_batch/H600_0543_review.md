## Finding
The function `rot_from_angles` incorrectly applies a negative sign to all input angles (`ax, ay, az = -rx, -ry, -rz`), which may result in incorrect rotation matrices when the intended rotation direction is not accounted for.

## Evidence
- tools/distant_world.py:47 - ax, ay, az = -rx, -ry, -rz

## Suggested fix
Remove the negative signs from the input angles if the rotation direction is intended to be preserved as provided by the caller.

## Validation needed
Test the function with known rotation angles and compare the output matrix to a trusted implementation (e.g., the C++ version referenced in the docstring).
