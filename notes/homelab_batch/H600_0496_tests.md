# tests: start_bridge.py:194 focus

Local-model review lead; NOT independently verified or applied.

## Finding
The `focus` function attempts to set focus on a window using `SetForegroundWindow`, but it may not work reliably if the window is not the one that last received input. This could lead to unexpected behavior in the overlay functionality.

## Evidence
- start_bridge.py:195 - SetForegroundWindow only works for the process that got the last input; a synthetic Alt tap satisfies that.

## Suggested fix
Ensure that the synthetic Alt key press is sufficient to allow `SetForegroundWindow` to take effect. If not, consider using `AttachThreadInput` to transfer input focus to the target window before calling `SetForegroundWindow`.

## Validation needed
Mock the `user32.SetForegroundWindow` and `user32.keybd_event` functions to verify that the focus is correctly set on the target window. Additionally, verify the behavior in-game by observing whether the overlay window gains focus as expected.
