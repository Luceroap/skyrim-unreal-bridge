## Finding
The function `rot_from_angles` computes a rotation matrix from Euler angles, but the implementation may not correctly handle the order of rotations or the sign conventions used in the corresponding C++ function `RotFromAngles`. This could lead to incorrect orientation of objects in the game world.

## Evidence
- unreal/SkyBridge/tamriel_live.py:37 - cx, sx, cy, sy, cz, sz = math.cos(ax), math.sin(ax), math.cos(ay), math.sin(ay), math.cos(az), math.sin(az)

## Suggested fix
Verify that the rotation order (X, Y, Z) and the sign conventions (negative angles) are consistent with the C++ implementation. For example, test with input angles (0, 0, 0) and expect an identity matrix. Test with (90, 0, 0) and expect a rotation around the X-axis by 90 degrees. Test with (0, 90, 0) and expect a rotation around the Y-axis by 90 degrees.

## Validation needed
Mock the input angles and verify the resulting rotation matrix. In-game verification would involve placing objects with known orientations and checking if they are rendered correctly.
