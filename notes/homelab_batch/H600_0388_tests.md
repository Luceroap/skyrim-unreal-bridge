## Finding
The function `convert_all` iterates over all static meshes in `/Game/Area2` and replaces any material that starts with `M_` (excluding certain exceptions) with a corresponding `MI_<key>` material instance. However, there is no explicit check to ensure that the `MI_<key>` material instance exists before attempting to assign it to the mesh. This could result in a runtime error if the material instance is missing.

## Evidence
- unreal/SkyBridge/remaster_materials.py:833 - mi = instance_for(name[2:])

## Suggested fix
Before assigning the material instance to the mesh, verify that the `MI_<key>` material exists. If it does not exist, log a warning or skip the assignment. For example, if `instance_for` returns `None`, the function should not attempt to call `mesh.set_material(i, mi)`.

## Validation needed
To validate this fix, a developer should mock the `instance_for` function to return `None` for a specific key and ensure that the function does not raise an error and logs a warning instead. Additionally, the developer should verify that the function correctly assigns the material instance when it exists.
